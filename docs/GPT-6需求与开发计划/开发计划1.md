## 2. A2：BUG-02 ETF 同步失败不得删除旧数据
文件：webapp/services/sync_service.py（`_run_etf_sync` :163-182、`_delete_etf_range` :214、`_fetch_etf_safe` :243、`_filter_jump_anomalies` :282、`_write_etf_data` :317）。

- [ ] 改为"先获取、校验，再单事务替换"：获取→跳变过滤校验通过后，同一事务内删旧区间+写入，一次 commit；消除独立提交删除造成的可见中间空档。
- [ ] 空结果不得删除：获取为空或源异常时保留原数据、记失败原因，不进入删除步骤。
- [ ] 写入异常回滚：`_write_etf_data`/删除路径异常时`db.rollback()`，单标的失败不污染后续 Session。
- [ ] 校验剔除部分行时默认中止该标的替换并保留原数据，不得用剩余行宣称完整替换成功；如允许部分写入，必须作为"部分成功"单独语义并在结果中标注，不与"成功"混同。
- [ ] 成功替换无重复键（同事务先删后写或 upsert），区间外记录不变。
- [ ] 继续使用现有任务机制；明确成功/部分成功/全部失败三态语义并落入任务结果（与 A10 逐证券结果字段对齐，written 只在 commit 成功后按实际 frame 计算）。
- [ ] 测试：源异常、空返回、插入中途异常（假 writer 中途抛错）均逐行保留原数据；A 失败不阻止 B 成功；成功替换无重复键、区间外不变；删除与写入之间无独立提交的中间空档。

验收（需求一§4）：源异常、空返回、插入中途异常均保留原数据；A 失败不阻止 B 成功；成功替换无重复键，区间外记录不变；没有独立提交删除造成的可见中间空档。
