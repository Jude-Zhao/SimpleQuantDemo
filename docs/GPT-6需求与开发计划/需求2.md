# SimpleQuantDemo 优化需求规格
更新日期：2026-09-11。

本文是已授权落盘的需求基线，不是开发计划。OPT-01为单一权威回测与指标框架，不以永久保留两个引擎为目标。严格因子资格与Web历史排除明细、约束仅提示、重复同步拒绝均已确认；OPT-02采用固定切分，但本轮可选、非阻塞。实现者不得擅自改变这些规则。

## 1. 项目背景和边界

SimpleQuantDemo 是 ETF 因子研究、回测和 Web 看板项目。仓库根目录包含 pyproject.toml、QWEN.md、core/、research/、webapp/、tests/、config/；本文路径均相对此目录。

- core/ 提供生产因子、分析、合成、优化、共享回测、数据适配器。
- research/ 提供独立因子池、研究入口和调参；不是所有 research 文件都属于可删除的重复回测。
- webapp/ 提供 FastAPI、业务服务、ORM和静态前端。
- 当前 Web 经 research/backtest.py 的兼容导出调用 core/backtest/engine.py。
- 当前研究主流程使用 research/bt_engine.py，调参脚本还含独立回测和指标。
- 默认数据库 sqlite:///./data/simple_quant.db 可由环境变量覆盖，不得当作测试库。
- Python及依赖以pyproject.toml为准，不假设本机环境齐全。

详细缺陷验收见同交接包的《需求1.md》（docs/GPT-6需求与开发计划/需求1.md，BUG修复需求）。两个文档需同时提供给执行Agent。

先完成测试隔离和数据安全；回测框架建立在已确认计算规则上，不移植错误公式。不擅自改默认参数、真实数据库、自定义FAA/EAA公式或研究/生产因子注册隔离。文档详尽不意味着引入复杂架构。

## 2. OPT-01：建立单一权威回测与指标框架，迁移后删除重复实现

### 2.1 目标和明确授权范围

整个项目仅保留一个权威的组合执行/账本回测实现，以及一套权威的绩效指标实现。Web、研究、调参和其他回测入口都调用该框架，不在入口本地重新计算净值、费用、换手或同名绩效指标。

交付一份完整详细的Markdown框架文档，涵盖设计、计算口径、各项指标公式、输入输出、调用示例及扩展边界。目标文档建议为 docs/统一回测与绩效框架.md，必须与最终实现一致，不能只有设计意图。

迁移并验证后删除旧的重复回测及指标实现，包括research下确属旧引擎、兼容桥接或重复账本的内容。当前阶段只记录此要求，不授权立即删除代码。不能把“research下的回测删除”扩大为删除研究因子、研究入口、参数搜索能力或研究结果输出功能。

### 2.2 第一性原理
1. 一个组合只能有一本权威账：期初资产、持仓变化、成交、费用、现金和期末净值必须守恒。
2. 相同输入与配置应产生相同结果；入口不同不是计算口径不同的理由。
3. 指标必须来自权威结果，不能由页面、导出或调参脚本重新发明。
4. 消除重复实现，而不是为了统一引入大型平台。
5. 允许一个内部依赖承担计算，但它必须是唯一封装后的权威实现。保留自研和bt两条可选执行路径不符合本需求。

### 2.3 当前待迁移位置
接手Agent须重新核查以下位置及全仓调用，清单是调查起点而非穷尽结果：

|位置|需处理的职责|
|---|---|
|core/backtest/engine.py|现有共享回测账本|
|research/backtest.py|当前Web依赖的兼容导出|
|research/bt_engine.py|独立bt执行引擎|
|research/main.py|研究入口、回测调用及汇总输出|
|research/tune_strategy_params.py|独立回测、绩效和参选评分|
|webapp/services/strategy_service.py|Web调用、结果序列化、绩效计算|
|core/evaluate.py|已有指标计算职责|
|tests/|旧入口测试及需迁移的语义回归|

对每处记录调用方、输入输出、保留的业务职责和迁移后位置。不要仅按文件名删除。因子IC、RankIC、ICIR等研究统计不是组合账本，但如包含在统一指标范围内也须有唯一计算定义，不能误删研究能力。

### 2.4 框架要求
- 权威实现位于现有core层的合适模块中，不依赖webapp或research。
- 业务入口负责加载数据、生成信号、目标权重及展示结果；框架负责执行、持仓、费用、净值和约定指标。
- 使用明确配置和结果类型，不引入插件总线、动态引擎选择平台或无需求的抽象层。
- 明确日线数据契约：date×sec成长表格式、时间类型、列顺序、唯一键、排序、价格口径、有限值和缺失值处理。
- 决策日、执行日、收益归属、初始资金、现金和费用完全遵循需求一批准后的规则。
- 默认年无风险利率为1%（0.01），所有入口一致；这不等于自动给现金计息。
- 目标权重、实际持仓权重、交易及净值不可混为同一字段。
- 返回足够核对交易与净值的结果；不要求保存逐笔盘口或完整撮合系统。
- 不支持的输入或能力明确拒绝，不偷偷走旧框架作为兜底。
- 选择保留自研实现还是封装现有库，在开发计划中依据功能、依赖和验收给出取舍；本需求不预先指定底层技术，但最终只能有一个权威路径。

### 2.5 统一指标范围
开发计划盘点所有现有对外指标和计算位置，为每项明确：名称、定义、单位、输入、公式、年化规则、无风险利率使用方式、样本标准差约定、空/短/零波动边界。

至少覆盖现有总收益、年化收益、年化波动率、Sharpe、最大回撤、净值、日收益、换手及费用；如页面/研究输出另有指标，保留其业务能力并统一定义，不能为本次迁移静默删除。

研究参数选择的综合评分可留在研究层，但必须消费权威框架的收益和指标；不得另建组合收益计算。IC等横截面研究指标可保留在core.analysis等职责清晰的模块，其范围及调用关系在文档中说明。

### 2.6 安全迁移与删除
1. 先确定输入输出契约及验收样例，再迁移调用。
2. 逐一迁移Web、研究主入口、调参、报告/导出及相关测试。
3. 临时兼容层可以用于迁移过程，但最终不得保留第二套计算。
4. 删除旧文件前证明无生产调用、无遗漏测试和文档引用；旧测试中的有效业务断言迁移到新框架，不能直接丢弃。
5. research/backtest.py等仅为旧调用存在的兼容层在调用迁完后删除，不永久保留用别名。
6. bt或其他依赖仅在确认全项目不再需要时移除；若选为唯一底层，则保留依赖但删除平行引擎。
7. 保留研究入口、因子池和调参业务能力。重写调用不等于删除业务功能。
8. 不为达到与旧错误结果一致而复制错误公式；历史结果变化须用确定性正确性用例解释。
9. 不批量改写已存历史策略结果。需要标识新旧口径时提出最小兼容方案，不自动进行数据迁移。

### 2.7 权威框架Markdown文档
必须包含:
- 职责边界、模块文件、公共导入路径和调用关系。
- 输入字段表、完整配置表、默认值（含1%无风险利率）、输出字段及单位。
- 从信号到成交到净值的时间轴及账户守恒公式。
- 初始建仓、持仓漂移、换仓、费用、末日信号、缺价/取消的具体例子。
- 全部交付指标的精确公式、边界约定与可核对的数值例子。
- 最小可运行合成数据调用示例，不依赖真实数据库/网络。
- Web、research、调参如何调用，如何消费指标，禁止哪些重复计算。
- 错误与告警契约、确定性排序、浮点容差。
- 测试命令、预期结果、环境要求、资源隔离方法。
- 旧入口到新入口的迁移映射及已移除实现说明。
- 新增指标的唯一实现位置、测试和文档同步规则，不建设通用插件平台。

文档必须足以让零上下文Agent调用和验证框架，不能引用聊天内容代替规则，不得与代码默认值和公式冲突。

#### 2.8 验收
- Web、研究和调参使用同一合成价格/目标输入时，权威净值、费用、换手和同名指标一致。
- 业务预处理不同造成的结果差异须能定位到输入；框架不能因调用方不同切换计算。
- 覆盖不交易、首次建仓、两资产漂移、完整换仓、非零费用、末日信号、缺失报价、初始亏损的精确数值测试。
- 相同规则下使用独立手算例子或参考公式验证，不以旧引擎输出为唯一真值。
- 全仓无仍执行的重复回测/指标公式；搜索结果允许测试参考公式、文档公式和真正不同的研究统计，但每项须可解释。
- 旧回测实现按范围移除，旧研究业务入口正常运行。
- 框架文档示例在隔离环境直接运行，输出与文档一致。
- 新框架不得依赖真实数据库或联网才能完成单元测试。

## 3. OPT-02：最小独立样本外验证
目标：区分历史参数筛选和独立评估，不把年度拆分当样本外。

当前research/tune_strategy_params.py在同一区间搜索、评分和展示。已确认采用固定时间切分，不建设walk-forward平台。用户随后明确本研究项可做可不做，因此本轮将OPT-02列为可选、非阻塞项：默认不要求运行真实区间的独立评估，不因未选日期阻塞其他修复。若实施，遵循以下规则；未实施则明确现有结果仅为样本内结果。

要求：参数选择区间早于评估区间且不重叠；仅使用选择区间参选；冻结后不在评估段搜索；因子可使用过去历史预热但不能用未来数据。输出区间、候选数、评分定义、冻结参数、基准参数和两段分别的成绩。使用OPT-01框架，不新增回测器。不自动写回默认配置。

限制：程序不能证明人类从未看过某段数据。已用于攻规则的区间不能重新声称完全未见。

验收：改变评估数据不改变参选；重叠区间拒绝；固定输入参选可复现；输出明确样本内/外。

可选项执行前提：实际评估前明确具体区间、基准参数和此前研究使用情况；不得随意指定日期并声称是真正未见样本。可用合成日期验证功能，此举不构成策略样本外有效性证据。非目标：完整walk-forward、多重检验平台、容量分析、盈利承诺。

## 4. OPT-03：明确缺失因子的资格规则
目标：缺少惩罚项不能隐式提高参选资格。当前core/synthesis/faa_eaa.py已复现缺类别标的仍得高分。

已确认规则：只考察实际启用且权重/指数>0的类别；当日全部必需因子为有限数值才有资格，NaN和正负无穷均不合格；缺必需项则合成分缺失、不入Top N；禁用类别不影响资格。合格数不足top_n不调仓，保留原仓，首次保持现金；没有交易不扣费，等待下一正式调仓。保持评分可比性和固定Top N，不增加缺失填补、预测或动态降级重新加权。保留旧仓时的行情估值另遵循BUG-09。

Web历史不合格明细要求：
- 覆盖回测范围内每个计划调仓决策日，不扩大为非调仓日逐日检查。
- 每个不合格标的记录决策日期、标的代码和名称、具体无效必需因子、所属类别和原因；多个无效因子不能仅保留其中一个而隐去其他原因。
- 同时记录当日合格数量、配置Top N和组合生成结果（正常生成或因资格不足跳过）。组合生成结果与后续成交取消状态区分，不能把生成目标误报为已成交。
- 即使合格数足够正常生成组合，也保存并展示被排除的标的。
- 资格结果随该次回测持久保存，通过API提供并在Web回测报告展示。Web不使用最新行情、因子或配置重置历史明细。
- 保留完整数据时FAA/EAA公式。明确资格判断输入及结果契约，不能在前端另写评分规则。

验收：必需项缺失不参选；禁用项缺失不影响；完整输入公式不变；不足N不偷偷改N、不无说明崩溃；分别测试合格充足/不足场景下明细完整；报告可定位具体日期与标的的无效因子；保存后改变数据或配置，再打开同一报告明细仍不变。

## 5. OPT-04：明确约束检查语义
目标：配置、提示与实际能力一致。当前Web事后检查部分组合，不代表历史和推荐均强制符合约束。

已确认：仅检查与提示，不新增强制求解器；不为满足约束更换标的、修改权重或成交，不因违反组合约束中止回测。输入合法性、资金守恒和成交可行性仍是强制要求，不能作为可忽略提示。

要求：页面明确非强制；逐次历史实际调仓检查；最新推荐单独检查；违反记录含日期、对象、约束、实际值、限制值；换手使用权威框架口径；不支持约束显式标记；检查不能改变原组合和收益。

验收：单票、类别数量/权重、换手样例准确提示；无违反不误报；历史和推荐不同分别检查；显示开关不改变回测。

非目标：自动修权重、通用求解器、两套复杂模式。

## 6. OPT-05：同步互斥和可信任任务结果
目标：避免重复请求并发覆盖，识别实际成功范围。

最小方案：在现有单进程机制增加互斥和上限，不引入外部队列。

要求：同证券、周期、重叠区间活动任务不能并发替换；重复的重叠活动请求明确拒绝并提示已有同步任务，不自动合并请求、不为被拒绝请求创建新任务；限制进程内并发；逐证券输出成功/失败、实际写入范围及原因；请求结束日不等于覆盖证明；复用接口单独重试失败证券；abort进程重启后内存状态不持久化。

验收：两个冲突任务只有一个执行替换；非冲突任务在上限内运行；失败可单独重试；覆盖展示实际写入而非请求参数；任务成功/失败都释放锁。

非目标：跨进程互斥、Redis/Celery、复杂断点续传和完整数据可观测平台。

## 7. OPT-06：可重复的工程验证
前置：BUG-01隔离完成。

要求：记录最低Python、依赖安装、安全测试和各层验证命令；核心指标断言数值；前端覆盖页面切换、异步失败、表单提交、配置往返；构建普通wheel并验证YAML和静态资源；源码目录外检查安装包导入与资源加载；全部资源临时化。

最小限制：优先已有测试工具，先覆盖已发现问题，不强制新增大型浏览器平台或CI服务。若构建证明没有资源遗漏，不为风险项制造修改。

验收：新隔离环境按文档可重复；不访问真实数据库/行情；包资源完整；离开源码可运行必要入口；失败真实返回，不靠断言变绿。安装资源遗漏尚未构建确认，不当作已发生事实。

## 8. 依赖和已确认决策

### 建议依赖
测试隔离→数据安全→权威框架与指标修复/迁移→删除重复实现。OPT-02独立评估为后续可选项，不阻塞上述交付。前端、安全、兼容可单独安排，具体任务顺序属于开发计划。

### 一致性要求
需求—BUG-07/08/09/11与OPT-01统一实现；OPT-03资格不足与框架不调仓规则一致；OPT-04换手不能另定义；OPT-05不能绕过事务保护。

### 已确认
- 单一权威回测与指标框架、全部调用迁移、删除重复实现，并提供完整公式与调用Markdown。
- 默认年无风险利率1%；默认交易费率万分之0.5，即0.00005、0.005%、0.5 bps。
- T+1收盘成交，先校验完整方案、再先卖后买；按实际买卖金额统一比例收费，允许分数份额，无最低手续费；按扣费后净值分配，现金不得为负。
- 换手=买卖金额绝对值合计/成交前净值，不除以二。
- 缺必要成交价则整次取消、不扣费、不自动重试；旧仓按最后有效价估值，恢复报价后计入变化。
- 年度稳定性分项改为年度盈利比例，其他评分部分不变。
- 严格因子资格、固定Top N；不足时不调仓，首次保持现金；Web展示并持久保存每个计划调仓决策日的不合格标的和具体原因，即使该日正常生成组合也记录。
- 组合约束只检查和提示，不强制调整或中止回测；合法性、资金守恒和成交条件仍强制成立。
- 重复重叠活动同步请求明确拒绝，不自动合并。
- 样本外验证采用固定切分，但本轮可选、非阻塞；没有确定真实区间时不编造日期或声称独立验证已完成。

资金分配公式与验收以需求—BUG-08为准，不在入口重新定义。业务决策无剩余阻塞项；框架底层选型、并发上限、数值求解与容差等技术细节由后续计划说明，不得改变已确认规则。
