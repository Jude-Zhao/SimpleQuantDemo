# SimpleQuantDemo 最小修复需求规格
更新日期：2026-09-11。

本文是已授权落盘的需求基线，不是开发计划。已同步本轮业务决策：默认交易费率万分之0.5、年无风险利率1%，以及执行、缺价和年度盈利比例规则。实现者不得擅自改变这些口径。后续修改以本文件为准。

## 1. 目标、项目背景与边界

接手者只需仓库及本需求交接包，不需要历史聊天。仓库根目录是同时包含 pyproject.toml、QWEN.md、core/、research/、webapp/、tests/、config/ 的目录。本文路径均相对于该目录。

SimpleQuantDemo 是 ETF 因子研究、策略回测和 Web 看板项目：

| 位置 | 职责及现状 |
| ---- | ---- |
| core/ | 因子、分析、合成、优化、共享回测、数据适配器 |
| research/ | 独立研究因子池、研究流水线、参数搜索 |

必须保留：
- 研究与生产因子注册表隔离。
- 行情统一后复权。
- 自定义 FAA：类别得分线性合成，Top N 等权；自定义 EAA：类别得分幂函数乘法合成，Top N 得分加权。不得改成论文原版。
- 现有 T 日信号、T+1 收盘执行的基本口径，除非后续明确修改需求。

最小修复原则：修复导致错误的必要环节和完整不变量，配套测试；不新增策略、因子、供应商、用户平台、任务中间件或前端框架。不自动清洗业务历史、不重跑全部策略、不覆盖默认参数，不修改无关用户工作。

与需求二的关系：用户已明确要求 OPT-01 最终形成单一权威回测和指标框架，迁移调用后删除重复实现。因此本文不要求永久保留两个引擎，也不允许先删除仍有调用方的实现。开发计划应合并重叠工作，避免修复多套实现后又无必要地重复重写。

## 2. 证据、安全和通用验收

证据分为：直接复现（原函数或原 JS 的合成输入运行）、静态确认（代码路径明确但未做完整集成验证）、条件性风险（依赖特定部署或输入）。不能将静态证据写成真实数据库已受损。

接手者须重新读取代码和相关测试；若函数已变化，记录差异后调整定位。每项修复必须包含隔离复现、明确预期、相关正常路径回归。不能运行的验证明确标为未执行。

在 BUG-01 完成前不得直接运行全量 pytest，或导入可能初始化真实数据库的应用入口。优先使用纯函数、内存数据库和测试替身。不得联网获取真实行情进行破坏性复现。

要求:

验收：以独立临时目录中的业务数据库哨兵验证测试前后内容不变；请求与后台任务只写测试库；禁网后普通测试可执行；业务失败导致成功用例失败；单独和组合执行结果一致。

## 4. 同步与缓存

### BUG-02：ETF 同步失败不得删除旧数据
位置：webapp/services/sync_service.py，_delete_etf_range、_fetch_etf_safe、_write_etf_data 及同步循环。

当前行为：删除并提交旧区间后才获取新数据；空结果无法恢复旧数据，写入异常缺少 rollback。证据：静态确认，另有转录控制流的内存数据库辅助实验，不属于原模块集成测试。

不变量：获取失败不改数据库；一次区间替换全部成功或全部不发生；单标的失败不污染后续 Session。

要求：先获取、校验，再单事务替换；空结果不得删除；写入失败回滚；校验剔除部分行时不能继续宣称完整替换成功，默认中止该标的替换并保留原数据；继续使用现有任务机制；明确成功、部分成功、全部失败的结果语义。

验收：源异常、空返回、插入中途异常均保留原数据；A 失败不阻止 B 成功；成功替换无重复键，区间外记录不变；没有独立提交删除造成的可见中间空档。

### BUG-03：宏观区间同步保留区间外历史
位置：webapp/services/macro_service.py，_sync_daily、_sync_monthly。

当前行为：有范围的获取对应无条件清表；月频来源范围不统一；删除单独提交。证据：静态确认。

要求：
- 有边界时只更新范围内日期；月频转换为月份后比较，包含结束月份。
- 所有来源统一裁剪；删除、写入在单事务中。
- 缺失的新字段值不是清除旧有效值的指令。
- 无日期边界时按返回键更新，不隐式清表。
- 本轮不新增全量重建功能。

验收：只同步二月，一月和三月不变；超范围返回不写入；缺字段保留旧值；转换或写入失败回滚；跨年月份边界正确。

### BUG-04：缓存不得将部分日期误判为完整命中
位置：core/data/cached_source.py，get_etf_price_by_codes。

直接复现：请求 2026-01-05 至 01-06，缓存只有 01-05，返回仍只有 01-05，源调用次数为零。

要求: 按证券判断区间覆盖；无法证明覆盖时不能宣称完整命中。允许重新获取该证券整个请求区间并按键合并，不强制建设精细缺口平台。主源缺少的证券交备用源补抓。按证券、时间及适用周期保证唯一性。补齐失败显式报告不完整状态或错误。不按自然日数量推断交易日缺失。

验收：超出缓存首尾日期触发获取；同批证券分别判断；主源只有 A 时备用源收到 B；合并无重复键；正常周末不误报为交易缺口。完整覆盖证明所依赖的信息必须在实现和测试中说明，不能仅检查首尾日期就宣称中间完整。

边界：永久同步水位、覆盖展示属于 OPT-05，本项不强制新增覆盖表。

### BUG-05：禁止未复权行情混入后复权链路
位置：core/data/akshare_source.py 的 get_etf_price_by_codes、_fetch_sina_price；webapp/services/sync_service.py 的跳变过滤；webapp/services/data_service.py 的缓存写入。

验收：后复权失败而未复权成功仍不污染缓存；两个写入入口准确保存 adj_factor；拆分例子不能经删除一行后混用价格尺度。

## 5. 回测、绩效和评分

### BUG-07：非调仓期间保持份额，不每日恢复目标比例
位置：core/backtest/engine.py；research/tune_strategy_params.py。

直接复现：A/B 初始各 50%，持有期 A 为 100→200→100，B 为 100→100→100，无调仓、无费，正确最终净值 1；当前共享引擎为 1.125。

不变量：无交易时份额不变，权重随价格漂移；交易基于成交前实际持仓，而非上次目标权重。

要求：维护正确的份额、现金与净值状态；保留选股和目标权重算法；独立调参公式不能残留同类错误。与 OPT-01 合并安排迁移，避免长久维护多套账本。明确 weights 字段是目标还是实际持仓，不能静默改语义。

验收：上述例子收益为零；非调仓日份额不变；调回相同目标比例时计入漂移引起的实际交易；平价无费时净值不变。

### BUG-08：统一成交与费用时间轴
状态：本节业务规则已确认，包括T+1收盘成交、统一比例费用、分数份额、不设最低手续费、扣费后净值分配、非负现金、买卖合计换手、先卖后买，以及缺少必要成交价时整次取消。

位置：core/backtest/engine.py 的 turnover/costs 和 shift(2)；research/tune_strategy_params.py 的 weights.diff() 与收益计算。

当前错误：共享引擎在 T 日按目标权重变化扣费，收益却按 T+1 收盘执行；没有 T+1 bar 仍扣费。调参首行 diff 导致建仓费用为零。

基本时间轴：T 收盘形成信号；T+1 收盘执行；T+1 收盘前旧持仓承担收益；新持仓首次影响 T+2 收盘收益行。这里 T+1、T+2 指下一个、下个交易日，不是自然日。

必须满足：
1. 费用属于真实执行日，不能在仅产生信号时扣除。
2. 无执行日则无交易、无费用。
3. 初始建仓不能漏费。
4. 费用单位明确，1 bps=0.0001。
5. 换手基于实际成交金额，不基于两个目标权重向量直接相减。
6. 账户守恒：持仓市值+现金=净值；不得通过隐含负现金融资支付费用。

已确认的执行与费用规则：
- 保留上述 T 日信号、T+1 交易日收盘成交时间轴。
- 买入和卖出均按实际成交金额收取同一比例费率 c；总费用 = c ×（实际买入金额合计 + 实际卖出金额合计）。费率可配置，统一默认万分之0.5，即 c=0.00005=0.005%，transaction_cost_bps=0.5。Web、研究、调参的权威框架调用使用同一默认，不能沿用各自旧费率；示例中显式指定的其他费率仅用于测试，不是默认值。
- 允许分数份额，不按整数份额或交易单位取整。
- 不设置最低手续费。
- 未成交不扣费；费用在成交日扣除，首次建仓不能漏费。
- 目标持仓按扣费后净值分配；费用由组合资金承担，不允许通过负现金融资支付。

已确认的资金分配计算：
- V_before：执行日按成交价格估值、扣除本次费用前的组合净值，包含旧持仓和现金。
- H_i：证券 i 在执行前按相同成交价格估值的持仓金额。
- w_i：本次目标权重；在本项目无杠杆、非持仓范围内使用，当前全仓策略满足 Σw_i=1。
- V_after：本次费用扣除后的组合净值。
- 目标持仓金额 H_target_i = w_i × V_after。
- 实际交易金额 Δ_i = H_target_i - H_i，正数为买入、负数为卖出；已卖出目标之外的旧持仓也必须纳入计算，其目标权重为0。
- 总费用 F = c × Σ|Δ_i|；V_after = V_before - F。
- 上述关系必须同时满足，不能按扣费前净值分配后再额外扣费，也不能按旧日目标比例估算费用。实现可求解标量方程 V_after + c × Σ|w_i × V_after - H_i| = V_before，具体数值算法及容差在开发计划中确定。
- 成交后现金 = V_after - ΣH_target_i。全仓目标时为0；如果合法输入保留现金权重，则剩余部分留在现金账户。本项不新增现金收益或杠杆策略。

首次单资产全仓建仓：本金 V、费率 c，买入金额 B = V/(1+c)，费用 F = V×c/(1+c)，成交后现金为0。例：V=100000、c=0.001，B约99900.099900元、F约99.900100元。展示可四舍五入，内部不能先按显示精度舍入再计费。

已确认换手：实际买入金额与实际卖出金额绝对值合计 / 成交前净值，不除以二。净值100、卖20买20，换手为40%。默认费率下买入10万元费用5元，卖出10万元费用5元，买卖各10万元合计10元。

已确认执行顺序：先检查完整调仓方案是否具备执行条件，通过后同一执行日按收盘价先卖后买，按扣费后净值分配。任一需要交易的证券缺少有效成交价，整次取消、原仓保留、费用为零；不部分成交、不自动重试，等待下一正式调仓。不能卖完后才发现买入无法执行。

估值和告警遵循BUG-09。

业务规则已确定，数值求解和浮点容差留给技术设计。不能只把 costs 整体 shift(1) 就宣称修复了持仓漂移和实际成交计费问题。

验收：单交易日无交易无费；买入金额1000、卖出金额500、费率0.001时费用为1.5；仅买入金额10、费率0.001时费用为0.01，不提升为最低手续费；允许非整数份额且无取整截断；首次建仓满足上述B和F公式；已有持仓调仓同时满足目标金额、实际交易费用及净值守恒方程，现金非负（浮点误差处理须有明确容差）；末日信号不制造范围外成交；零费与 BUG-07 一致；换仓日旧持仓损益、成交、费用和新持仓结存能够逐笔对账。

### BUG-09：缺失行情不吞掉恢复报价后的损益

### BUG-11：绩效纳入初始本金并明确 Sharpe 定义
位置：webapp/services/strategy_service.py 的 _compute_metrics；core/evaluate.py；research/tune_strategy_params.py 的 _metrics；OPT-01 要求全部入口最终调用单一指标实现。
直接复现：净值 [0.999,0.999,0.999] 被报告总收益0和最大回撤0；当前 Sharpe 使用 CAGR 而不是平均超额收益。
已确认：默认年无风险利率为 1%，参数数值 0.01。此默认适用于统一指标框架及全部调用入口，不得残留各自硬编码的2%。这是风险调整的比较基准，不代表现金账户自动获得1%收益；现金计息属于独立执行模型。
计算定义（初始归一化本金1，每日净收益r_t）：
- 总收益=∏(1+r_t)-1。
- 净值为累计收益乘积。
- 当日峰值=max()，截至当日全部净值。
- 回撤=当日净值/当日峰值-1；最大回撤取最小值。
- 年交易日数默认252；年化收益按有效收益期间数计算，装饰性初始行不计一个收益期间。
- 日无风险收益=(1+0.01)^(1/252)-1；参数被覆盖时使用对应年利率。
- 日超额收益=日净收益-日无风险收益。
- Sharpe=mean(日超额收益)/std(日超额收益,ddof=1)×sqrt(252)。
要求：不能用已扣首日费用的首个净值作原始本金；支持明确传入年无风险利率，默认1%，不为此新增前端控件。历史结果不能因为新默认而被无提示覆盖。
验收：上述样例总收益及最大回撤均为-0.001；手算确定性序列验证总收益、年化、波动率、Sharpe；少于两个有效值或零标准差时兼容返回0且无穷值；所有入口同定义。空序列、净值非正等边界的输出规则在开发计划中明确，不得用任意填零掩盖非法数据。
