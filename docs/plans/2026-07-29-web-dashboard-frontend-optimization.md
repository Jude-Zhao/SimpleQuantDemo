# 前端页面优化方案

> **针对**: `docs/plans/2026-07-29-web-dashboard-design.md` 中的前端设计（第6节）
> **目标**: 在保持"原生 JS + ECharts"技术栈的前提下，提升视觉辨识度、信息密度与交互体验

---

## 一、设计系统升级（Design System）

### 1.1 色彩体系：淡雅莫兰迪灰调

当前设计文档指定"浅色背景 + 蓝色主色调"，容易滑向高饱和的 fintech 默认配色。本方案采用**低饱和莫兰迪色系**——所有颜色都带有灰调，视觉上安静、克制、耐看，长时间盯盘不疲劳。

#### 核心配色哲学

- **中性色占绝对主导**（背景、文字、边框占 90% 以上面积）
- **强调色极度克制**（仅用于当前页指示、主按钮、关键链接，占比 < 3%）
- **语义色去饱和**（成功/警告/危险不用鲜绿/橙/红，而用灰绿/灰褐/灰玫瑰，降低焦虑感）
- **数据色优先于 UI 色**（图表中的数据线条是视觉焦点，UI 框架退后）

#### 全局 Token 表

| Token | 浅色模式 | 暗色模式 | 用途 |
|-------|---------|---------|------|
| `--bg-base` | `#f5f4f2` | `#1c1c1e` | 页面背景（暖白 / 暖黑灰，非纯白纯黑） |
| `--bg-surface` | `#faf9f7` | `#252527` | 卡片/面板背景 |
| `--bg-elevated` | `#ffffff` | `#2e2e30` | 悬浮层/模态框（浅色模式略提亮） |
| `--border-subtle` | `#e0ded9` | `#3a3a3c` | 卡片边框、分割线 |
| `--border-hover` | `#c8c5be` | `#4a4a4c` | 边框 hover 状态 |
| `--text-primary` | `#2c2c2c` | `#c8c6c2` | 主标题、重要数据 |
| `--text-secondary` | `#6e6e6e` | `#8a8a8a` | 辅助说明、标签 |
| `--text-muted` | `#9e9e9e` | `#5a5a5c` | 禁用状态、占位符 |
| `--accent` | `#7a8494` | `#a0a8b8` | 主强调色（低饱和灰蓝，极克制） |
| `--accent-subtle` | `#e8eaee` | `#3a4048` | 强调色弱背景（标签、hover 高亮） |
| `--accent-hover` | `#6a7484` | `#b0b8c8` | 强调色 hover 状态 |
| `--success` | `#6b8a6b` | `#7a9a7a` | 正收益、校验通过（灰绿） |
| `--success-subtle` | `#e8f0e8` | `#2a3a2a` | 成功色弱背景 |
| `--warning` | `#a88d6a` | `#baa07a` | 警告、中等风险（灰褐） |
| `--warning-subtle` | `#f5f0e8` | `#3a352a` | 警告色弱背景 |
| `--danger` | `#a06a6a` | `#b88080` | 负收益、校验失败、最大回撤（灰玫瑰） |
| `--danger-subtle` | `#f5e8e8` | `#3a2a2a` | 危险色弱背景 |
| `--info` | `#6a7a8a` | `#8a9aaa` | 信息提示（灰蓝） |

#### 图表数据配色（莫兰迪六色）

所有图表线条/柱子使用以下低饱和色系，保证多线并存时视觉和谐：

```javascript
const chartPalette = {
  light: [
    '#7a8494',  // 灰蓝（主强调色，用于第一条线）
    '#9a8a7a',  // 暖灰褐
    '#7a9a8a',  // 灰绿
    '#a09080',  // 浅赭
    '#8a8a9a',  // 灰紫
    '#8a9a7a',  // 鼠尾草绿
  ],
  dark: [
    '#a0a8b8',  // 亮灰蓝
    '#b8a898',  // 亮暖褐
    '#90b0a0',  // 亮灰绿
    '#c0b0a0',  // 亮赭
    '#a8a8b8',  // 亮灰紫
    '#a0b090',  // 亮鼠尾草绿
  ],
  up:    { light: '#6b8a6b', dark: '#7a9a7a' },  // 涨/正（灰绿）
  down:  { light: '#a06a6a', dark: '#b88080' },  // 跌/负（灰玫瑰）
  zero:  { light: '#b0b0b0', dark: '#5a5a5c' },  // 基准线（中灰）
};
```

**关键改进**:
- 主强调色从高饱和蓝/青绿改为 **低饱和灰蓝 `#7a8494`**，在界面中几乎隐形，不会与数据图表争夺注意力
- 背景使用**暖白 `#f5f4f2` / 暖黑灰 `#1c1c1e`**，比纯白纯黑柔和，降低长时间盯盘疲劳
- 成功/危险色从鲜绿/鲜红改为**灰绿 `#6b8a6b`** 和**灰玫瑰 `#a06a6a`**，传递信息但不制造焦虑
- 暗色模式不是简单反色，而是采用低明度的暖灰黑底，配合降低饱和度的同色系，整体保持统一灰调

### 1.2 字体规范

当前设计文档未指定字体，这是隐含的隐患。

```css
/* 全局字体栈 */
--font-sans: -apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif;
--font-mono: "SF Mono", "Fira Code", "Cascadia Code", "Noto Sans Mono CJK SC", monospace;
```

**层级规范**:

| 层级 | 大小 | 字重 | 行高 | 用途 |
|------|------|------|------|------|
| Display | 28px | 600 | 1.2 | 页面大标题（如"因子看板"） |
| Heading | 18px | 600 | 1.4 | 区块标题（如"IC 时序"） |
| Body | 14px | 400 | 1.6 | 正文、表格内容 |
| Caption | 12px | 400 | 1.5 | 辅助说明、时间戳 |
| Data | 24px | 600 | 1.0 | KPI 数字（年化收益、夏普比率等） |
| Data-Small | 16px | 500 | 1.2 | 次要指标 |

**重要约束**: 中文不使用 `font-style: italic`。需要强调时改用 `font-weight: 600` 或背景色高亮。

### 1.3 间距系统

采用 4px 基准的 spacing scale，保持全局一致性：

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 24px;
--space-6: 32px;
--space-8: 48px;
```

卡片内边距统一用 `--space-5 (24px)`，卡片间隙用 `--space-4 (16px)`，区块间距用 `--space-6 (32px)`。

## 二、全局布局重构

### 2.1 边栏导航（Sidebar）

**当前问题**: 固定 200px 宽、使用 emoji 图标、底部只有版本号。

**优化方案**:

```
┌────────┬─────────────────────────────────────────────────────┐
│        │  顶部栏: 面包屑 + 页面操作 + 全局搜索               │
│  64px  ├─────────────────────────────────────────────────────┤
│  图标  │                                                     │
│  栏   │              主内容区 (可滚动)                       │
│        │                                                     │
│        │                                                     │
│        │                                                     │
└────────┴─────────────────────────────────────────────────────┘
```

- **宽度**: 从 200px 收窄为 **64px 图标栏 + 240px 展开面板（hover/点击展开）**，或采用可折叠的 64px/240px 双态设计
- **图标**: 用 inline SVG 替换 emoji，保证跨系统一致。图标线宽 1.5px，激活状态填充 `--accent` 色
- **结构**:
  - 顶部：Logo（简化版图标）
  - 中部：6个导航项（首页、因子看板、策略运行、标的池、分类约束、设置）
  - 底部：主题切换 + 用户/系统状态指示器（用 8px 圆点，绿色=正常，黄色=缓存同步中，红色=数据源异常）
- **交互**: 当前页面项在 sidebar 中显示左侧 3px 宽 `--accent` 色指示条（而非整块背景变色）

### 2.2 顶部栏（Top Bar）

设计文档中顶部栏只有"系统状态"，过于单薄。建议增加：

- **面包屑**: `首页 / 因子看板 / 动量因子分析` — 支持点击返回
- **全局搜索**: `Ctrl+K` 唤起，可快速跳转页面、搜索 ETF 代码、查找因子
- **页面级操作**: 当前页面的主操作按钮（如因子页的"运行计算"、策略页的"▶ 运行策略"）
- **数据新鲜度指示**: "数据更新至 2026-07-28 15:00" + 刷新按钮

### 2.3 内容区布局策略

当前设计采用大量纵向堆叠，导致单页内容过长。建议引入 **"仪表网格"（Dashboard Grid）** 概念：

- 使用 CSS Grid 定义内容区：`grid-template-columns: repeat(12, 1fr); gap: 16px;`
- 小卡片占 3 列（1/4 宽），中卡片占 6 列（1/2 宽），大卡片占 9-12 列（3/4 到全宽）
- 卡片可以**拖拽调整顺序**（用 SortableJS 或原生 Drag API），用户按需排列

## 三、各页面具体优化

### 3.1 首页 Dashboard（信息密度提升）

**当前结构问题**: 统计卡片 → ETF走势+因子排名 → 最近运行 → 净值曲线。纵向太长，关键信息分散。

**优化后的三行布局**:

```
┌─────────────────────────────────────────────────────────────────────────┐
│  [统计卡片行]  标的池 28 | 因子 6 | 今日运行 3 | 系统 ● 正常              │
├─────────────────────────────┬───────────────────────────────────────────┤
│                             │  [因子IC排名]  实时更新                     │
│    [ETF走势大图]             │  1. 动量因子   0.045 ▲  +12%              │
│    支持多周期切换+缩放手势    │  2. 反转因子   0.032 ▲  +8%               │
│                             │  3. 波动率因子 -0.028 ▼  -5%              │
│                             │                                           │
│                             │  [最近策略运行]                             │
│                             │  ┌─────────────────────────────────┐     │
│                             │  │ 线性因子组合  07-29  年化12.5%   │     │
│                             │  │ MVO优化       07-28  年化 8.3%   │     │
│                             │  └─────────────────────────────────┘     │
├─────────────────────────────────────────────────────────────────────────┤
│  [净值曲线对比]  策略选择 ▼ | 时间范围 ▼ | 基准对比 ▼                     │
│                                                                         │
│   (大尺寸多线图表，占满整行)                                              │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

**关键改进**:
1. **统计卡片（KPI Cards）**: 不只有数字，增加**环比变化小标签**（如"+2 只 较上周"），用颜色区分正负。卡片 hover 时显示微型 sparkline（用 ECharts 渲染的 120×30px 折线图，无坐标轴）
2. **ETF 走势与因子排名并排**: 走势占 8 列，排名占 4 列，避免单栏过宽或过窄
3. **因子排名增加趋势**: 每个因子后显示"较上一期变化百分比"，用 ▲▼ 和颜色标注
4. **净值曲线前置**: 作为最重要的历史对比，放在首屏下半部分，而非页底

**关键改进**:
1. **左侧因子列表 + 右侧分析区**: 左侧固定 280px，列出所有因子复选框，点击某个因子在下方展开其详情卡片（名称、类别、方向、公式、参数）
2. **时序图 Tab 样式优化**: 不用普通按钮式 Tab，改用"胶囊式"（Pill-style）切换，当前项有背景色，hover 有过渡动画
3. **分组收益改为真柱状图**: 不用 ASCII 字符，用 ECharts 渲染带数据标签的柱状图，第5组和第1组用不同颜色（绿/红）直观展示多空
4. **热力图交互**: 鼠标悬停单元格显示相关系数（保留两位小数），并高亮对应的行和列

2. **权重滑块优化**: 滑块拖动时实时显示百分比，支持键盘方向键微调（1%步进）。所有因子权重之和超过 100% 时，最后修改的滑块自动回弹并显示红色提示

4. **运行按钮状态机**: 未配置 → 灰色禁用；配置完成 → 主色可点击；运行中 → 加载动画（按钮内显示 spinner + "计算中..."，同时禁用其他操作）

### 3.4 标的池管理（表格增强）

**优化方案**:

1. **表格头部固定**: 滚动时表头 sticky 置顶
2. **列排序**: 点击列头可排序（规模、加入时间等）
3. **行 hover 效果**: hover 某行时显示快速操作按钮（编辑、移除），平时隐藏减少视觉噪音
4. **类别标签**: "宽基"/"行业"/"商品"等类别用彩色小标签（Pill Tag）展示，而非纯文本
5. **批量操作栏**: 选中多行后，顶部浮现批量操作栏（批量移除、批量修改类别）
6. **空状态设计**: 标的池为空时，不显示空白表格，而是显示插图 + "暂无标的，点击添加"引导

### 3.5 分类约束（可视化规则流）

## 五、交互体验优化

### 5.1 加载与空状态

| 场景 | 当前设计 | 优化方案 |
|------|---------|---------|
| 页面首次加载 | 无明确方案 | Skeleton Screen（骨架屏），模拟内容区域的大致轮廓，避免白屏 |
| 数据加载中 | 无明确方案 | 卡片内显示 Spinner（居中，24px），文字"加载中..." |
| 图表数据请求 | 无明确方案 | 图表保留上次数据，叠加半透明遮罩 + spinner |
| 空状态 | 无明确方案 | 空状态插图（可用纯 CSS/SVG 绘制）+ 引导文字 + 操作按钮 |
| 错误状态 | 无明确方案 | 错误提示卡片（红色边框），显示错误信息 + "重试"按钮 |

### 5.2 微交互（Micro-interactions）

1. **按钮点击**: 点击时 scale(0.98)，释放恢复，给予触觉反馈感
2. **卡片 hover**: 轻微上移（translateY(-2px)）+ 阴影加深，而非简单的边框变色
3. **数据更新**: 数字变化时使用计数动画（从旧值滚动到新值，持续 300ms）
4. **Tab 切换**: 内容区使用淡入淡出（opacity 0→1，150ms），避免突兀切换
5. **Toast 通知**: 操作成功/失败时，右上角滑入 toast（成功绿色、错误红色、警告黄色），3 秒后自动消失，支持手动关闭

### 5.3 键盘快捷键

```
Ctrl+K      全局搜索
Ctrl+1~6    快速切换页面（1=首页, 2=因子, 3=策略, 4=标的池, 5=分类, 6=设置）
Ctrl+R      刷新当前页面数据
Esc         关闭模态框/搜索面板
```

### 5.4 实时数据推送

策略运行等耗时操作，建议后端使用 **SSE（Server-Sent Events）** 推送进度：

```
客户端 POST /api/strategies/run
服务端立即返回 run_id
客户端连接 SSE /api/strategies/runs/{run_id}/stream
服务端推送: {"progress": 30, "stage": "计算因子..."}
服务端推送: {"progress": 100, "stage": "完成", "result": {...}}
```

前端进度条实时更新，用户无需等待页面转圈。

### 7.3 主题切换实现

```javascript
// theme.js
const themes = { light: { /* 变量值 */ }, dark: { /* 变量值 */ } };

function applyTheme(name) {
  const root = document.documentElement;
  const vars = themes[name];
  for (const [key, val] of Object.entries(vars)) {
    root.style.setProperty(`--${key}`, val);
  }
  // 同步更新 ECharts 实例
  window.dispatchEvent(new CustomEvent('themechange', { detail: name }));
  localStorage.setItem('theme', name);
}
```

所有 ECharts 实例监听 `themechange` 事件，调用 `dispose()` + `init()` 重新渲染。

## 八、性能优化

1. **ECharts 懒加载**: 首屏只渲染可见区域的图表，滚动到视口内再初始化
2. **虚拟滚动**: 标的池表格数据量大时，使用虚拟滚动只渲染可视行
3. **防抖请求**: 搜索框输入防抖 300ms，滑块拖动节流 100ms
4. **Chart 实例池**: 页面切换时不销毁图表实例，放入对象池复用
5. **CSS Contain**: 卡片使用 `contain: layout paint`，减少重排范围
