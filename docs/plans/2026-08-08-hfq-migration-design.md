# 行情数据统一后复权（hfq）改造设计文档

**版本**: V1.0
**日期**: 2026-08-08
**状态**: 已实施（2026-08-08）

---

## 一、背景与问题

### 1.1 现象

看板中 **恒生ETF（513660.SH）** 显示"过去120天下跌超过 50%"，明显不合理。排查确认为**前端展示正确，问题出在数据库行情数据本身**：

- 数据库中 513660 在 **2026-04-21 单日从 3.128 跌到 1.569（-49.84%）**，是典型的 **1:2 基金份额拆分**（净值恰好减半），但价格序列中没有被复权处理，留下断崖。
- 全库扫描 `>±15%` 单日跳变，**28 只 active 池子里超过 10 只有未复权拆分/分红断崖**，且多集中在 2025-2026 年（如 512480 半导体 -50.7%、513770 港股互联网 -49.15%、512800 银行 -49.69%、515880 通信 -50.7% 等），会直接污染"过去 N 天涨跌 / 动量 / 波动率 / 回撤"等因子。

### 1.2 根因

| 环节 | 现状 | 问题 |
|------|------|------|
| 主源 AkShare | `fund_etf_hist_sina`（新浪） | **返回不复权原始价格**，无任何复权处理 |
| 次源 Baostock | `adjustflag="2"`（前复权） | 对 ETF 拆分/分红的复权处理**不可靠**，513660 拆分未被处理 |
| 入库 | 无任何校验 | 未复权断崖数据直接写入 `etf_daily_bar` |

---

## 二、方案决策：统一采用后复权（hfq）

### 2.1 为什么选后复权

内置因子（动量/反转/波动率）全部基于**收益率**（`close.pct_change`），**只要复权因子正确，前复权与后复权计算的收益率完全一致**。两者差异体现在**数据稳定性与可复现性**：

| 维度 | 前复权 qfq | 后复权 hfq ✅ |
|------|-----------|--------------|
| 复权基准 | 最新价 | 上市首日 |
| 历史价格稳定性 | 随最新价漂移，每次新分红/拆股整条曲线平移 | **固定**，不随未来事件改变 |
| 历史回测 | 含未来除权信息，有前视偏差、不可复现 | **无前视、结果可复现** |
| 与当前因子的适配 | 收益率类因子数值与 hfq 相同 | 收益率类因子数值与 qfq 相同 |

**结论**：后复权历史序列稳定、可复现、无前视偏差，更适合因子研究与回测。本项目统一采用 hfq。

### 2.2 后复权下的"现价失真"处理

后复权最新价 = 上市以来累计复权价，**不是真实市价**（对高分红基金会明显偏高）。为兼顾看板"现价"等需要真实价展示的场景，同步时**额外计算并保存每日累计复权因子 `adj_factor`**：

- `adj_factor(t) = hfq_close(t) / raw_close(t)`
- 真实现价 = `hfq_close / adj_factor`（等价于 raw_close）

## 三、数据源改造

### 3.1 主源 AkShare → 腾讯 fqkline 后复权

**现状**：`core/data/akshare_source.py` 使用 `ak.fund_etf_hist_sina`（新浪，不复权）。

**改造**：`get_etf_price_by_codes` 优先调用新增的腾讯接口 `_fetch_hfq_price`，新浪不复权作为最后兜底。

**为什么选腾讯（而非东财）**：设计初曾计划用东财 `fund_etf_hist_em(adjust="hfq")`，但实测**当前网络环境无法访问东财域名**（`push2his.eastmoney.com` 直连与代理均断开）；baostock 后复权对 ETF 拆分复权失效（513660 在 2026-04-21 前后复权仍断崖 -49.84%）。腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get` 可达且 hfq 复权正确（拆分日价格连续，最大单日波动 10%）。

- 接口：`https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param={hs_code},day,{start},{end},640,{fq}`
  - `hs_code`：如 `sh513660`（复用 `_to_sina_code`）
  - `fq`：`hfq`（后复权）/ 空（不复权）
- **单次上限 640 条**，按年份分段拉取拼接；带重试（3 次）应对偶发 SSL 抖动
- 同一标的拉两遍：`hfq`（主数据）+ 空（用于 `adj_factor = hfq_close/raw_close`）
- 新浪 `fund_etf_hist_sina` 保留为最后兜底（返回不复权，adj_factor 为 NaN）

### 3.2 次源 Baostock → 后复权

**现状**：`core/data/baostock_source.py` 使用 `adjustflag="2"`（前复权）。

**改造**：改为 `adjustflag="1"`（后复权）。baostock 不直接提供每日复权因子，兜底数据 `adj_factor` 列置空。

## 四、入库断崖校验

在 `webapp/services/sync_service.py` 写入 `etf_daily_bar` 前，对每只标的价格序列做**单日涨跌幅校验**：

- 计算相邻交易日 `close` 的单日涨跌幅
- 若某日 `|涨跌幅| > 15%`：判定为疑似未复权的拆分/分红/数据异常
  - **默认拦截该条记录**（不写入），并记录到任务结果 `warnings`
  - 同时前台提示用户该标的可能存在除权事件，需确认数据源
- 阈值可配置（`config` 中 `data.jump_threshold`，默认 15%）

**重要修正（实施中发现）**：腾讯 hfq 数据带 `adj_factor` 列，复权已正确，**跳过该校验**——此时 >15% 的单日波动是真实行情（如 2024-09 A 股暴涨，创业板/成长 ETF 单日 ±16~20% 均真实存在），拦截会造成真实数据缺失。校验仅作用于**兜底源**（Sina 不复权 / Baostock，无 `adj_factor` 列），防止未复权拆分断崖入库。

> 说明：正常 ETF 单日波动极少超过 15%；超过往往是除权或数据错误。拦截可防止坏数据再次污染因子。

## 五、数据库表结构变更

`webapp/models/market_data.py` 的 `EtfDailyBar` 新增一列：

| 字段 | 类型 | 说明 |
|------|------|------|
| adj_factor | Float | 每日累计后复权因子 `hfq_close / raw_close`，用于还原真实市价；次源数据可为空 |

```python
class EtfDailyBar(Base):
    ...
    adj_factor = Column(Float)  # 新增：后复权累计因子
```

同步时写入；因子计算层读取 `close` 逻辑不变。

## 七、影响面与验证

### 7.1 影响面

| 模块 | 影响 |
|------|------|
| 因子计算（动量/反转/波动率） | 数值变化（因历史价格重算为 hfq），但收益率口径正确 |
| IC / RankIC / 回测 | 重新基于 hfq 计算，结果更可信 |
| 看板收益/回撤/现价 | 收益/回撤更正确；现价若展示需用 `close/adj_factor` 还原 |
| 分钟线 | 本次**不迁移**（分钟线按需缓存，且无拆分断崖问题），保持现状 |

### 7.2 验证项

1. **断崖复检**：全库扫描 active 标的，确认无 `>±15%` 单日跳变。
2. **口径抽查**：对 513660，比对第三方渠道的后复权价格，确认 2026-04-21 前后价格连续（涨幅约 0%）。
3. **因子回归**：重跑因子看板，确认恒生ETF"过去120天"跌幅回归合理区间（由 -53% 修正为真实跌幅）。
4. **现价还原**：抽查 `close/adj_factor` 与行情软件真实现价一致。

## 九、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 东财接口返回字段名/格式差异 | 拉取失败或映射错误 | 上线前先对单只标的（513660）做接口试拉验证 |
| 东财对部分 ETF 无历史 | 个别标的无数据 | 保留 baostock 兜底；试拉后核对覆盖行数 |
| hfq 现价失真 | 看板现价展示误导 | 用 `close/adj_factor` 还原展示；文档标注 |
| 断崖校验误伤（单日真实涨跌>15%） | 数据被误拦 | 阈值可配置；拦截记入 warnings 供人工复核 |
| 重同步耗时 | 全量 28 只 | 后台线程 + 进度条（沿用现有同步架构） |
