## 1. 职责边界与模块

**全项目只有一本权威账**：组合执行/份额/现金/费用账本与绩效指标实现位于 `core/backtest`；Web（`webapp/services/strategy_service.py`）、研究主流程（`research/main.py`）、调参（`research/tune_strategy_params.py`）只负责加载数据、生成信号/目标权重、序列化展示，不重新计算净值、费用、换手或同名指标。不依赖 `bt`、`quantstats` 等外部回测/绩效库。

| 文件 | 职责 |
|---|---|
| `core/backtest/models.py` | `ExecutionConfig` / `BacktestConfig` / `MetricsConfig` / `TargetPlan` / `BacktestResult`（frozen dataclass，避免循环导入） |
| `core/backtest/execution.py` | `solve_target_amounts`：扣费后目标分配的唯一数值求解（二分法） |
| `core/backtest/engine.py` | `execute_backtest`（唯一逐日账本执行入口）；`run_backtest`（长表+得分便捷入口） |
| `core/backtest/targets.py` | `build_target_weights`：全部计划决策日的资格检查、稀疏目标与决策日志 |
| `core/backtest/metrics.py` | `calculate_metrics` / `calculate_yearly_returns`：唯一绩效计算 |
| `core/synthesis/eligibility.py` | `build_category_scores_with_details`：携带因子身份的类别构建与资格明细（不导入 Web） |

公共导入路径（`core.backtest.__init__` 统一导出）：

```python
from core.backtest import (
    BacktestConfig, BacktestResult, ExecutionConfig, MetricsConfig, TargetPlan,
    build_target_weights, calculate_metrics, calculate_yearly_returns,
    execute_backtest, run_backtest, solve_target_amounts,
)
from core.synthesis import build_category_scores_with_details
```

调用关系：`run_backtest` = pivot 行情 → `build_target_weights` → `execute_backtest` → 附加 decision_log/rebalance_dates/config_snapshot。研究主流程直接调用 `build_target_weights + execute_backtest`（等价拆分）。依赖方向：Web services → core；禁止 services → api、Web → research。

**因子资格（OPT-03）**：类别得分由 `build_category_scores_with_details` 构建——任一必需因子实例当日无效（NaN=missing，±inf=non_finite）则该类别得分 NaN；FAA/EAA 跨启用类别取有效性 AND（普通 `+`/`*`，不再 `add(fill_value=0)`/`mul(fill_value=1)`）。启用（正权重/正指数）但为空的类别是配置错误，显式拒绝。禁用（权重/指数为 0）类别不参与合成、其无效不影响资格。完整数据时归一化/等权/乘法公式与旧实现完全一致。`category_score_from_matrices`（跳 NaN 平均）仅保留给仪表盘研究统计展示，不用于组合资格。

## 2. 数据契约（输入）

### 2.1 close（execute_backtest 直接输入）与 price_data（run_backtest 输入）

| 项 | 约定 |
|---|---|
| 索引 | `DatetimeIndex`，日线日期，唯一、递增、无时区；重复日期/乱序直接 `ValueError`（不能 groupby 取平均掩盖） |
| 列 | 唯一证券代码；`target_weights`/`factor_scores` 的列必须与之完全一致 |
| 数值 | 正且有限为有效报价；NaN / ±inf / 非正 → 当日无有效报价（走缺价逻辑），不猜测 |
| `price_data`（长表） | 含 `date/sec/close`（`pivot_price_field` 校验重复 (date,sec) 并转宽表） |
| 交易日历 | `run_backtest`/`build_target_weights` 的 `trading_dates` 取 **price_data 全部日期并集**，不得与有效因子日期做 intersection 删除缺信号日期（因子预热不移动 5d 分块起点）。全市场某日完全缺失无法从输入证明日历完整——输入日历责任在调用方，框架不虚构成交日 |

### 2.2 target_weights（稀疏目标）

| 项 | 约定 |
|---|---|
| 索引 | 实际产生目标的决策日子集（**不 ffill**）；每个日期必须在 close 日期内；重复决策日报错 |
| 缺行 | = 没有新订单（资格不足跳过的日期不生成行） |
| 全零行 | = 明确清仓（与缺行严格区分） |
| 数值 | 行内完整、有限、非负；部分 NaN 非法。行和 `<= 1`；仅 `<= 1e-12` 的浮点超额按原比例归一到 1，真实超配报错 |
| 单位 | 权重（目标金额 / 扣费后净值）。`BacktestConfig.max_weight/min_weight` 是选股配置，只在显式配置时传入优化器；Web 提示性组合约束不传入优化器 |

## 3. 时间轴与账户守恒

**时间轴**（T、T+1、T+2 均指输入交易日，不是自然日）：

1. T 收盘产生稀疏目标行（决策日）；
2. T+1 收盘执行：按 T+1 收盘价估值 `V_before` → `solve_target_amounts` 求扣费后净值 → 先卖后买、按腿收费、转份额；
3. T+1 收盘前旧持仓承担收益，新持仓首次影响 T+2 收盘收益行；T+1 当日收盘后净值已按新持仓计（买入价=当日收盘 → 当日不产生该腿的收益）；
4. 末日信号没有后续交易日 → 只记录 `unexecuted_end`，不制造范围外成交；
5. 同一日只能有一个待执行方案；取消的订单不复用、不 ffill 重生成、不自动重试（等待下一正式调仓重新决策）。

**资金分配**（需求1 BUG-08 确认方程，`execution.py` 唯一实现）：

```
残差函数  residual(x) = x + c·Σ|w_i·x − H_i| − V_before      （c=费率，H_i=执行前持仓金额）
求解      二分法 100 次，区间 [0, V_before]；sum(w)≤1 且 c<1 时残差严格递增、包根
输出      after = V_after；target = w·V_after；delta = target − old；fee = c·Σ|delta|
容差      tol = 1e-10 · max(1, V_before)；|after+fee−V_before| ≤ tol 且 after−Σtarget ≥ −tol
          容差内结算残差由费用吸收置零；超容差抛 ValueError，不剪裁负现金掩盖
无交易    仅当所有 |delta| ≤ tol 时记 no_trade 且不改变原仓
```

**守恒不变量**（执行日逐日校验）：`成交后现金 + Σ持仓市值 = V_before − fee`；现金非负；净值非正报错。

**缺价规则**（BUG-09）：缺价持仓按最后有效价估值；恢复报价后完整计入价格变化（禁止未来回填）；需要交易的集合 = 旧持仓 ∪ 正目标权重（保守边界），其中任一证券执行日无有效报价 → **整次取消、原仓保留、零费用**；份额非零但从无有效价格属非法状态直接报错。

### 3.1 具体例子（全部有测试锚定）

| 例子 | 数据 | 结果 |
|---|---|---|
| 初始建仓 | 本金 V=100000、费率 c：`B = V/(1+c)`，`fee = V·c/(1+c)`，现金 0 | c=0.00005：fee ≈ 4.99975 |
| 全仓 A 换 B（平价） | `V_after = V(1−c)/(1+c)`，`fee = c(V+V_after)`，换手 = (V+V_after)/V | `test_full_switch_with_fee_matches_b1_formula` |

## 4. 指标公式（唯一实现 `metrics.py`；指标不四舍五入，展示层才舍入）

记 `r_t` 为有效收益期间收益（`daily_returns` 去掉首行基准），`n = len(daily_returns) − 1`，`A = annualization(252)`，`rf_d = (1+0.01)^(1/252) − 1`（配置 rf 时按其计算）：

| 指标 | 公式 | 边界 |
|---|---|---|
| `total_return` | `equity[-1] − 1`（含全部费用） | 空输入 0 |
| `annual_return` | `(1+total)^(A/n) − 1` | `n=0` → 0 |
| `annual_volatility` | `std(r, ddof=1)·√A` | `n<2` → 0（持现金的零收益日仍是有效期间，不 drop 0） |
| `sharpe` | `mean(r−rf_d)/std(r−rf_d, ddof=1)·√A` | `n<2` 或分母 0 → 0 |
| `max_drawdown` | `min(equity/cummax(equity) − 1)`；净值含装饰首行 1.0，峰值自动含初始本金；传入不含初始行的序列先头部拼接 1.0 | `[0.999,0.999,0.999]` → **−0.001**（不是 0） |
| `sortino` | `mean(r−rf_d)·√A / √mean(min(r−rf_d, 0)²)`（全样本分母、不中心化） | 无下行或 `n=0` → 0（有限值约定）。注意：名义收益全零且 rf>0 时每日超额均为 −rf_d，属"存在下行"，结果为 `−√A ≈ −15.87`，是定义的正确结果 |
| `calmar` | `annual_return / |max_drawdown|` | 回撤 0 → 0 |
| `win_rate` | 正收益期间数 / 非零收益期间数 | 无非零期 → 0 |
| `turnover_sum` | `Σ turnover`（不从 weights.diff 重算） | |
| `cost_sum` | `Σ fees / initial_cash`（相对初始本金累计费用） | 另提供 `fee_amount_sum = Σ fees` |
| `rebalance_count` | execution_log 中 `status=executed` 次数（no_trade 不计） | |
| `calculate_yearly_returns` | 日收益按年分组 `(1+r) 连乘 − 1` | 首行基准 0 不改变年度值；空 → `{}` |

非法输入（NaN/inf 收益、非正净值、净值与日收益长度不一致、`annualization<=0`、`rf<=-1`）→ `ValueError`；合法空/无期间 → 全 0 指标。

**可核对数值例子**（`test_exact_baseline_case`）：净值 `[1.0, 0.999, 0.999, 0.999]`、日收益 `[0, −0.001, 0, 0]` → 有效期间数 3、`total_return=−0.001`、`max_drawdown=−0.001`、年化 `(1−0.001)^(252/3)−1`。

## 5. 最小可运行示例（内存数据，无数据库/网络）

以下脚本可直接保存为 `examples_doc_backtest.py` 在仓库根目录运行（`python examples_doc_backtest.py`）：

```python
import pandas as pd

from core.backtest import (
    BacktestConfig,
    ExecutionConfig,
    execute_backtest,
    calculate_metrics,
    run_backtest,
)

# ① 直接账本：宽表 close + 稀疏目标（价格 100/110/121，首日全仓，零费）
dates = pd.to_datetime(["2026-01-05", "2026-01-06", "2026-01-07"])
close = pd.DataFrame({"A": [100.0, 110.0, 121.0]}, index=dates)
targets = pd.DataFrame({"A": [1.0]}, index=dates[:1])  # 仅决策日有行

r = execute_backtest(close, targets, ExecutionConfig(transaction_cost_bps=0.0))
print(r.equity_curve.tolist())     # [1.0, 1.0, 1.0999999999999999] ≈ 1 / 1 / 1.1（T+1 收盘 110 买入，T+2 反映 121/110）
print(r.trades.iloc[0]["price"])   # 110.0

# ② 非零费首日建仓：V=1、费率 c=0.5bps → T+1 净值 = 1/(1+c)
r2 = execute_backtest(
    pd.DataFrame({"A": [100.0] * 3}, index=dates),
    targets,
    ExecutionConfig(transaction_cost_bps=0.5),
)
print(r2.equity_curve.iloc[1])           # 0.9999500024998751 = 1/1.00005
print(calculate_metrics(r2)["cost_sum"])  # 4.9997500124993755e-05（费用/本金）

# ③ 便捷入口：长表 + 因子得分
price_long = close.rename_axis("date").reset_index().melt(
    "date", var_name="sec", value_name="close"
).assign(
    open=lambda d: d.close, high=lambda d: d.close, low=lambda d: d.close,
    volume=1000.0, amount=1000.0,
)
scores = pd.DataFrame({"A": [1.0, 1.0, 1.0]}, index=dates)
r3 = run_backtest(
    price_long,
    scores,
    BacktestConfig(top_n=1, max_weight=1.0, transaction_cost_bps=0.0),
)
print(r3.decision_log[0]["status"], r3.execution_log[0]["status"])  # target_created executed
```

输出锚点：① 净值 `1 / 1 / 1.1`、成交价 `110`（T+1 收盘执行，零费）；② T+1 净值
`1/(1+c)`、`cost_sum = fee/initial_cash`；③ 决策日志与执行日志状态。上述数值由
`tests/test_execution_timeline.py::test_timeline_zero_fee`、
`tests/test_backtest.py::test_run_backtest_charges_turnover_cost_on_execution_day`
与 `tests/test_backtest_metrics.py` 的断言覆盖，文档与实现不一致视为文档缺陷。

## 7. 错误契约、确定性与容差

- **输入非法一律显式拒绝**（ValueError/OptimizationError）：重复日期/列、乱序索引、带时区索引、部分 NaN 目标行、真实超配（行和 > 1+1e-12）、未知因子、启用空类别、持仓无价、非法配置。不支持的能力不静默回退旧框架。
- **确定性排序**：优化器按分数降序、同分按证券代码升序（EqualWeight）；ScoreWeighted 先按代码稳定排序再按分数降序。因子类别按配置顺序，决策日志按日期升序，exclusions 按 (sec, category, factor, instance_index) 排序。
- **浮点容差**：金额 `1e-10·max(1, V_before)`；权重行和超额 `1e-12`；二分 100 次（区间宽 < `V_before·2⁻¹⁰⁰`）。
- **JSON 契约**：Web `result_summary`（schema_version="2"）只保存有限数值或 null（`_json_safe` 把 NaN/Infinity 转 null）；写入前用 `RunDiagnostics` 嵌套 schema 严格校验。
