# 数据源限流加固需求文档

更新日期：2026-09-13。状态：待审核（同日按审核意见修订：决策 5 重试口径精确化、第 7 节文档修正清单落实）。

本文是需求基线，不是开发计划。方案选择与关键口径已经用户确认（2026-09-13 讨论），实现者不得擅自变更第 4 节的已确认决策。详细改动清单见同目录《开发计划.md》。

## 1. 背景与问题

行情主数据源为腾讯 fqkline 接口（`web.ifzq.gtimg.cn/appstock/app/fqkline/get`，后复权 hfq）。当前同步链路存在三个问题：

1. **请求总量过大**：接口单请求上限 640 行（约 2.6 年交易日），当前按年分段，且每只 ETF 需拉 hfq 与未复权 raw 两个序列（raw 仅用于计算 `adj_factor = hfq_close / raw_close`）。全区间（2021-01-04 起）每只 12 个请求，31 只全量约 372 个请求。
2. **请求节奏过快**：全局节流为固定 0.4s 间隔（150 请求/分钟）。实测约 96 个请求、38 秒内即触发 WAF IP 级封禁（HTTP 501 + waf.tencent.com 拦截页，封禁持续分钟级），估计阈值在 ~100 请求/分钟量级。
3. **失败后无熔断**：主源被 IP 级拦截后，同步 worker 仍逐只重试（每只再烧 3 个重试请求），拖长任务且加剧封锁；2026-09-12 全量同步 31 只仅 6~8 只成功，任务耗时 2 分钟以上。

## 2. 目标

1. 标的池扩展到 40-50 只时，全量重建与日常同步均能在 WAF 阈值下完成，不触发 501。
2. 万一仍被限流：同步任务快速止损（熔断中止剩余标的），任务结果明确展示失败原因与"未尝试"标的。
3. 单次同步的请求总量降至现状的 1/4（每只 12 → 3）。

## 3. 非目标（明确不做）

- **不做增量同步默认/断点续跑**（原方案乙的同步语义变更）：删 raw 后全量重建本身已足够便宜（50 只 150 请求），增量机制的边际收益不再值得行为变化与改动量。
- **不更换数据源**（原方案丁）：baostock 对 ETF 复权无效（2026-09-12 实证）、东财被墙、新浪无复权；腾讯是当前网络环境唯一可行主源。
- **不做限流重试调度/代理池/多源负载均衡**。
- **不改变数据保留原则**：获取失败不删除旧数据、单事务区间替换等既有语义不变。

## 4. 已确认决策

1. **采用方案丙：删除 raw 序列拉取与 adj_factor + 2 年分段 + 限速抖动 + WAF 拦截不重试 + 熔断。**（2026-09-13 用户确认"方案丙不错"，节奏设计确认"可以"）
2. **删除 adj_factor 的依据**（2026-09-13 讨论确认）：
   - baostock 备用源已删除，当前为单一可信 hfq 源 + 失败快速中止，"断崖校验拦截未复权数据"的威胁模型不再成立；
   - 断崖校验对腾讯数据本就空转（hfq 行永远带 adj_factor 列，校验直接跳过）；
   - adj_factor 的值目前无任何下游消费（因子、回测、图表均只用 close/volume/amount）；
   - hfq/raw 历史均不可变（2026-09-13 实证：159908.SZ 库内 1381 行与次日接口逐日一致，最大差异 0.0），将来若需真实价，可通过一次性 raw 回补恢复（50 只 × 3 请求），删除是可逆的。
3. **断崖校验降级为"仅告警不剔除"**：单日涨跌幅超阈值的行照常写入，记入任务 warnings 展示；不再有"校验中止(rejected)"状态。保留对源数据毛刺的可观测性，不误杀真实行情（如 2024-09-30 大涨）。
4. **限流参数可配置**：节流区间与熔断阈值进 `datasource` 配置，代码内保底默认值。
5. **WAF 拦截（HTTP 501/拦截页）不重试**：封禁为分钟级，重试无益且可能加剧；网络异常、坏 JSON 及其他非 200 瞬时服务端错误（502/503/504 等）保留指数退避重试。

## 5. 关键设计口径

- **请求数账本**（每只每序列 640 行上限，2 年分段 = 3 段/序列，仅 hfq）：

| 场景 | 请求数 | 预计耗时（均值 1s/请求） |
|---|---|---|
| 当前缺口 25 只补齐 | 75 | ~80 秒 |
| 50 只全量重建 | 150 | ~2.5 分钟 |
| 50 只日常增量窗口 | 50 | ~1 分钟 |

- **限流假设声明**：~100 请求/分钟的 WAF 阈值是从 2026-09-12 失败同步反推的估计值，真实窗口与计数方式不可观测。设计为"估计值定参数 + 抖动留 40% 余量 + 熔断兜底"三层，参数实测后可调。
- **数据口径变化声明**：`close` 仍为 hfq 后复权价（因子/回测消费口径不变）；删除 adj_factor 后系统不再具备真实价还原能力；页面展示的价格本就是 hfq 价（与现状一致，非回归）。
- **熔断语义**：同步 worker 内连续 N 只（默认 3）标的报 `TencentSourceError` → 中止剩余标的、逐只记为 `skipped`（"未尝试"）、任务消息提示稍后重试；成功/其他类型失败清零计数。

## 6. 验收标准

1. 全量 pytest 通过（删改增明细以实施报告为准）。
2. 生产代码中不再存在 `adj_factor` / raw 拉取逻辑（grep 可验证）。
3. 真实验证：对当前 25 只缺口做全区间同步，75 请求量级内完成、全部成功、无 501。
4. 模拟 WAF 拦截：连续 3 只被拦后任务完成、剩余标的展示"未尝试"、源调用恰为 3 次（单元测试覆盖）。
5. 旧数据库可直接使用：同步正常读写，旧 adj_factor 列残留无影响。
