## 一、项目概述

### 1.1 核心目标

构建一套用于多因子筛选ETF的极简量化系统，主要用于**多因子ETF周度轮动投资**。

### 1.2 系统架构

系统包含一个公共核心层和一个运行入口。公共核心层负责投研的核心计算逻辑；投研系统在流程编排、输出形态和可视化能力上保持独立。

| 模块/子系统 | 目录 | 用途 | 核心功能 |
|------------|------|------|----------|
| 公共核心层 | `core/` | 统一计算逻辑 | 数据结构校验、数据预处理、因子接口、IC/RankIC/ICIR、共线性分析、因子合成、组合优化、调仓日生成 |
| 投研系统 | `research/` | 回测验证 | 支持参数调整、策略迭代、绩效分析、可视化输出 |

### 1.3 设计原则

1. **模块化设计**: 每个模块（数据预处理、因子构建、共线性分析、因子合成、组合优化）间接口清晰，支持随时替换
2. **核心逻辑复用**: 投研复用 `core/` 中的因子接口、IC计算、因子合成、组合优化等纯计算逻辑，避免研究结果漂移
3. **入口独立**: `research/` 只负责自身的运行流程、配置、输出文件和可视化，不重复实现核心计算逻辑
4. **用户因子开放**: 系统提供标准因子接口，用户可自行编写Python因子逻辑，包括宏观映射因子

## 二、数据模块

### 2.1 数据来源

- **API**: AkShare（https://akshare.akfamily.xyz/）
- **本地存储**: CSV文件
- **数据字典**: https://akshare.akfamily.xyz/data/index.html

### 2.2 数据类型

| 数据类型 | 描述 | 字段说明 |
|----------|------|----------|
| ETF量价数据 | 日频行情 | date, sec, open, high, low, close, volume, amount |
| 高频经济指标 | 日频宏观因子 | 19个指标（信用利差、期限利差、汇率、PE等） |
| ETF产品池 | 28只非债券ETF | 证券代码列表 |

### 2.3 数据质量与结构要求

| 数据项 | 要求 |
|--------|------|
| 日期格式 | 读取后统一转换为 `datetime64[ns]`，兼容 `YYYY-MM-DD` 与 `YYYY/M/D` 等原始格式 |
| ETF行情结构 | 长表结构，columns=[date, sec, open, high, low, close, volume, amount] |
| 宏观指标结构 | 宽表结构，index=date, columns=宏观指标名称 |
| 产品池结构 | `list[str]`，证券代码格式如 `510300.SH`、`159928.SZ` |
| 日期对齐 | ETF行情与宏观指标需按交易日对齐 |
| ETF缺失值 | 按 `sec` 分组处理；上市前或无交易数据不做跨证券填充 |
| 宏观缺失值 | 默认按日期向前填充（ffill），是否额外滞后由用户因子自行处理 |
| 数据时点 | 系统默认当前输入数据的最新日期为最新收盘数据，不自动处理宏观数据发布滞后 |

### 2.4 数据接口设计

```python
# core/data/base.py

        """
        pass

    @abstractmethod
    def get_universe(self) -> list[str]:
        """
        获取ETF产品池
        返回: 证券代码列表，如 ['510300.SH', '512690.SH', ...]
        """
        pass
```

### 3.1 数据预处理

| 处理项 | 说明 |
|--------|------|
| 缺失值处理 | ETF行情按 `sec` 分组处理，上市前缺失不填充；宏观指标默认按日期向前填充（ffill） |

### 3.2 因子构建

#### V1版本内置与可扩展因子

| 因子名称 | 描述 | 默认参数 |
|----------|------|----------|
| 动量因子 | 系统内置，N日收益率 | N=5 |
| 波动率因子 | 系统内置，N日年化波动率 | N=20 |
| 宏观映射因子 | 用户自定义，宏观指标到ETF的映射逻辑 | - |

#### 因子接口设计

```python
# core/factors/base.py
from abc import ABC, abstractmethod
import pandas as pd

class FactorBuilder(ABC):
    """因子构建器抽象基类"""

    @abstractmethod
    def build(
        self,
        price_data: pd.DataFrame,
        macro_data: pd.DataFrame,
        universe: list[str]
    ) -> pd.DataFrame:
        """
        构建因子
        参数:
            price_data: ETF价格数据
            macro_data: 宏观因子数据
            universe: ETF产品池
        返回:
            DataFrame, index=date, columns=sec, values=因子值
        """
        pass

    @property
    @abstractmethod
    def name(self) -> str:
        """因子名称"""
        pass
```

#### 多因子数据结构

V1版本采用 `dict[str, pd.DataFrame]` 表示多因子面板：

```python
factor_panel = {
    "momentum_5": momentum_df,       # index=date, columns=sec
    "volatility_20": volatility_df,  # index=date, columns=sec
    "macro_custom": macro_factor_df  # index=date, columns=sec
}
```

选择该结构的原因：

1. 与单个因子构建器返回值一致，用户自定义因子只需返回一个 `date × sec` 的DataFrame
2. 因子名称明确，便于配置、日志、IC统计、共线性分析和因子合成
3. 相比长表结构更适合横截面计算；相比MultiIndex列结构更易读、易调试
4. 系统内部可在需要时转换成长表或矩阵结构，但对外接口保持简单

#### 宏观映射因子边界

V1版本不在系统层面内置固定的宏观映射模型。系统只负责提供完整、准确、结构稳定的价格数据、宏观数据和产品池，并校验用户因子输出是否满足 `index=date, columns=sec` 的结构要求。宏观指标如何映射到ETF由用户在自定义因子中自行实现。

#### 因子预处理

- **去极值**: 3σ原则
- **标准化**: Z-Score标准化

### 3.3 IC / RankIC / ICIR计算

#### 计算口径

| 指标 | 定义 |
|------|------|
| 未来收益 | 基于未来5个交易日收益计算，`forward_return[t] = close[t+5] / close[t] - 1` |
| IC | 同一日期横截面上，因子值与未来5个交易日收益的Pearson相关系数 |
| RankIC | 同一日期横截面上，因子值排名与未来5个交易日收益排名的Spearman相关系数 |
| ICIR | 指定窗口内IC序列的均值除以标准差，`ICIR = mean(IC) / std(IC)` |

V1默认在调仓日样本上统计IC、RankIC、ICIR；如需在全部交易日上滚动统计，可通过配置扩展。

#### 时点假设

1. 因子日期为 `t`，收益标签使用 `t` 到 `t+5` 的收盘价收益
2. 当日收盘后可产生因子；研究系统默认取用户输入数据中的最新日期作为最新收盘数据
3. 系统不自动处理宏观数据发布滞后，用户自定义因子需自行避免未来函数
4. 回测末尾不足5个未来交易日的样本不参与IC、RankIC、ICIR计算

### 3.5 因子合成

#### 合成方法

- **方法**: ICIR半衰期加权
- **参数**: `half_life_periods` (默认20)
- **公式**: `weight_i = 0.5 ** (i / half_life_periods)`，其中 `i=0` 表示最近一期ICIR，`i=1` 表示上一期ICIR

#### 合成接口设计

### 3.6 组合优化

#### 优化约束

| 约束条件 | 默认值 | 说明 |
|----------|--------|------|
| 持仓数量 | Top 5 | 可配置参数 `top_n` |
| 单个标的权重上限 | 50% | 可配置 |
| 权重下限 | 0% | 不可做空 |
| 权重归一化 | sum=1 | 满仓 |

#### 优化方法

简单等权分配：按因子值排序，取Top N标的，等权分配。若 `top_n` 与 `max_weight` 约束导致无法满仓（例如 `top_n=1` 且 `max_weight=0.5`），V1版本直接报错，不自动保留现金。

## 四、调仓逻辑

### 4.1 调仓频率

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `rebalance_freq` | 'weekly' | 可选: 'weekly' / 'monthly' |
| `rebalance_day` | 0 | 周内第N个交易日调仓，默认0（每周第一个交易日） |

### 4.2 调仓规则

- 调仓日: 每周期的第一个交易日
- 调仓方式: 全仓切换
- 新买标的: 按优化权重全额买入
- 卖出现金: 清仓非目标标的

### 4.3 交易成本

V1版本支持固定费率模型：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `transaction_cost_bps` | 5 | 单边交易费率，单位bps |

回测中按组合换手扣费：

```python
turnover = sum(abs(new_weight - old_weight))
cost = turnover * transaction_cost_bps / 10000
```
