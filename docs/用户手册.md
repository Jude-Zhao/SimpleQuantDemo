# SimpleQuantDemo 用户手册

本手册面向量化研究员，说明如何运行当前系统、查看结果、调整参数，以及如何基于系统做 ETF 周度轮动投研。

## 1. 系统能做什么

SimpleQuantDemo 是一个本地数据驱动的多因子 ETF 周度轮动系统。当前版本包含一个入口：

| 系统 | 命令入口 | 用途 |
|------|----------|------|
| 投研系统 | `python -m research.main` | 读取本地数据，构建因子，计算 IC/ICIR，合成因子，回测，输出图表和统计 |

research 使用**独立的研究因子池**（`research/factors/` + `research/factor_config.yaml`），可混合使用自定义研究因子与 core 内置因子（动量/波动/反转），策略合成统一走 FAA / EAA。示例 `research/factor_config.yaml` 默认配置：

| 因子类别 | 因子实例 |
|----------|----------|
| 动量 | momentum(20) / momentum(60) |
| 波动 | volatility(20) / volatility(60) |
| 反转 | reversal(5) |
| 研究示例 | price_position(20) |

系统也支持用户自己写 Python 因子，包括宏观映射因子。

## 4. 数据说明

当前系统（research / webapp）统一从 SQLite 数据库 `data/simple_quant.db` 读取数据：

| 表 | 内容 |
|------|------|
| `etf_daily_bar` | ETF 日频行情（字段 sec_code/trade_date/open/high/low/close/volume/amount/source） |
| `macro_daily` | 日频宏观指标宽表（14 个标准字段，如 shibor_3m / cn_gov_10y 等） |
| `universe_items` | 标的池（sec_code / sec_name / is_active） |

数据读取层（`core/data/sqlite_source.py` 的 `SqliteDataSource`）会自动处理：

1. ETF 行情长表格式（date/sec/open/high/low/close/volume/amount）。
2. 宏观指标宽表格式，按交易日对齐并前向填充。
3. 标的池与行情证券代码一致性校验（universe 必须都有行情）。

> 说明：`data_example/` 目录保留，但已不再被任何代码引用。

## 6. 投研输出怎么看

投研系统会输出以下文件：

| 文件 | 说明 |
|------|------|
| `summary.csv` | 回测统计指标 |
| `equity_curve.csv` | 每日策略净值 |
| `weights.csv` | 每日持仓权重 |
| `factor_stats.csv` | IC、RankIC、ICIR 序列 |
| `synthesized_scores.csv` | 合成因子分数 |
| `warnings.txt` | 共线性警告和被剔除因子 |
| `equity_curve.png` | 净值曲线图 |
| `factor_stats.png` | IC、RankIC、ICIR 图 |
| `latest_weights.png` | 最新持仓权重图 |

### 6.1 `summary.csv`

核心字段：

| 字段 | 含义 |
|------|------|
| `total_return` | 区间总收益 |
| `annual_return` | 年化收益 |
| `annual_volatility` | 年化波动率 |
| `sharpe` | 夏普比率 |
| `max_drawdown` | 最大回撤 |
| `sortino` / `calmar` | Sortino / Calmar 比率 |
| `win_rate` | 日胜率 |
| `turnover_sum` | 累计换手 |
| `cost_sum` | 累计交易成本（bt 引擎未配置成本模型，恒为 0） |
| `rebalance_count` | 调仓次数 |

> 口径说明：绩效指标（年化/波动/夏普等）由 `quantstats` 计算，与 webapp 看板自算口径可能略有差异（如无风险利率、年化方式）。两者回测引擎也不同（research 用 bt，webapp 用自研引擎），结果仅作对比参考。

### 6.2 `weights.csv`

每一行是一个交易日，每一列是一只 ETF。权重大于 0 的列就是当天持仓。

检查最新持仓可以用：

```powershell
Get-Content research\output\backtest_results\weights.csv -Tail 5
```

### 6.3 `factor_stats.csv`

这个文件包含三类指标：

1. `ic`：因子值与未来 5 日收益的横截面 Pearson 相关。
2. `rank_ic`：因子排名与未来 5 日收益排名的 Spearman 相关。
3. `icir`：滚动 IC 均值除以滚动 IC 标准差。

当前研究入口默认只在调仓日样本上统计 IC/RankIC/ICIR。

> 说明：`factor_stats.csv` 是**独立的因子评价产出**（研究因子好坏），不参与 FAA/EAA 组合构建。组合由 `research/factor_config.yaml` 的分组 + 策略合成生成。

## 8. 如何调整参数

因子与策略参数分开配置：

- **因子清单/窗口**：编辑 `research/factor_config.yaml`（新增因子实例、改窗口、增删分组）。
- **策略参数**：编辑 `research/config.py` 或使用 CLI 参数。

策略配置位于：

```text
research/config.py
```

常用参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `start_date` | `2019-11-01` | 起始日期 |
| `end_date` | `None` | 结束日期，None 表示用到数据末尾 |
| `strategy_type` | `faa` | 策略类型：`faa` / `eaa` |
| `top_n` | 5 | 持仓数量 |
| `max_weight` | 1.0 | 单个标的权重上限 |
| `rebalance_freq` | `monthly` | 调仓频率：`weekly` / `monthly` |
| `weight_mode` | `equal` | 目标权重方式：`equal`（FAA）/ `score`（EAA） |
| `class_weights` | `{}` | FAA 类间权重，空则所有非空类等权 |
| `exponents` | `{}` | EAA 类缩放系数 α，空则所有非空类为 1 |
| `beta` | 1.0 | EAA 整体缩放系数 β |
| `forward_return_horizon` | 5 | IC 使用未来 N 日收益（因子评价） |
| `ic_min_observations` | 10 | 横截面最少有效 ETF 数（IC 计算） |
| `icir_window` | 20 | ICIR 滚动窗口 |
| `icir_min_periods` | 10 | ICIR 最少样本 |
| `collinearity_threshold` | 0.7 | 共线性阈值（因子评价） |

临时改区间优先用 CLI 参数 `--start-date` / `--end-date`；改策略类型 / Top N / 调仓频率用 `--strategy` / `--top-n` / `--rebalance-freq`。类间权重、指数 β 等复杂参数在 `research/config.py` 里配。

## 10. 如何新增一个自定义因子

系统要求因子输出为：

```python
DataFrame(index=date, columns=sec, values=factor_value)
```

research 自定义因子的标准流程（三步）：

1. 在 `research/factors/` 下新建因子类，继承 `core.factors.base.FactorBuilder`，用 `research.factors.registry.register_factor` 注册到 **research 因子池**（不会污染 core/web 的全局注册表）。
2. 在 `research/factor_config.yaml` 的分组里登记该因子实例（name + params）。
3. 运行 `python -m research.main`，因子自动被解析并参与构建与合成。

示例：一个简单的 10 日反转因子（`research/factors/reversal_10.py`）：

```python
from core.factors.base import FactorBuilder
from core.factors.utils import pivot_price_field, validate_factor_matrix
from research.factors.registry import register_factor


@register_factor("reversal_10")
class Reversal10Factor(FactorBuilder):
    registry_name = "reversal_10"
    display_name = "10日反转"

    def __init__(self, window: int = 10):
        self.window = window

    @property
    def name(self) -> str:
        return f"reversal_{self.window}"

    def build(self, price_data, macro_data, universe):
        close = pivot_price_field(price_data, field="close", universe=universe)
        factor = -close.pct_change(self.window, fill_method=None)
        validate_factor_matrix(factor, universe, name=self.name)
        return factor
```

然后在 `research/factor_config.yaml` 的某个分组（或新建分组）登记：

```yaml
  research_demo:
    display_name: "研究示例"
    factors:
      - name: price_position
        params: { window: 20 }
      - name: reversal_10
        params: { window: 10 }
```

> 因子名称解析顺序：先查 research 因子池，再 fallback 到 core 内置 registry，因此可以混合使用自定义因子与 core 内置因子（momentum / volatility / reversal）。

### 10.1 研究后如何迁移到 webapp 上线

1. 把因子类文件移入 `core/factors/builtin/<新类>/`（或直接在 core 侧按同名新建）。
2. 在 `core/factors/builtin/factors.yaml` 的分类中登记该因子实例。
3. 从 `research/factor_config.yaml` 移除（或改为引用 core 同名因子）。

由于 research 与 core 遵循完全相同的 `FactorBuilder` 协议（`build → date × sec`），迁移无需修改因子实现。

## 11. 如何写宏观映射因子

当前系统不内置固定宏观映射模型。用户可以自己把宏观数据映射为 `date × ETF` 因子矩阵。

示意：

```python
from core.factors.utils import pivot_price_field

close = pivot_price_field(price_data, field="close", universe=universe)
macro_signal = macro_data["汇率：美元指数"].pct_change(20)

# 示例逻辑：美元指数上涨时偏向黄金ETF，否则偏向权益ETF
factor = close.copy() * 0.0
factor.loc[:, :] = -macro_signal.reindex(factor.index).values.reshape(-1, 1)
factor["518880.SH"] = macro_signal.reindex(factor.index)
```

注意事项：

1. 宏观数据是否滞后由用户因子自行处理。
2. 不要在因子里使用未来数据。
3. 输出列必须与 `universe` 顺序一致。
4. 上市前或无行情阶段可以保留 NaN。
