一、定位

    以 Python 为技术栈，面向 ETF 做量化策略的运行看板。在 Web 
    页面上展示因子表现、运行多种策略、调参、管理标的池，并对组合做分类约束优化与检查。

    ---

    二、核心能力

    1. 因子表现展示
     - Web 看板展示当前各因子的表现（如 IC、收益、换手、分组收益等，具体指标待定）
     - 支持因子对比与历史表现回看

    2. 策略运行能力（Web 页面可调参）


    ┌───────────────────────────────┬───────────────────────────────────────────┐
    │ 策略                          │ 说明                                      │
    ├───────────────────────────────┼───────────────────────────────────────────┤
    │ 线性因子组合策略              │ 多因子线性加权打分/组合，参数可在页面调整 │
    ├───────────────────────────────┼───────────────────────────────────────────┤
    │ 均值方差优化 (MVO)            │ 经典 Markowitz 均值方差优化，参数可调     │
    ├───────────────────────────────┼───────────────────────────────────────────┤
    │ Black-Litterman (BL) 模型优化 │ BL 模型，结合主观观点与先验，参数可调     │
    └───────────────────────────────┴───────────────────────────────────────────┘

     - 运行策略时，Web 页面可调整参数（权重、约束、观点矩阵等）
     - 运行结果在看板可视化展示

    3. 标的池管理
     - 可对对标池 ETF 进行增删（动态维护投资标的集合）
     - 标的池状态持久化，供策略与看板使用

    4. 因子库目录（插件式）
     - 后端代码中专设一个目录存放因子计算的 .py 文件
     - 设计原则：因子以插件 / 约定优于配置的方式组织，新增因子 = 新增一个 py 文件（+ 
       注册），无需改动核心引擎
     - 目录结构示例：
     1   quant_engine/factors/        # 因子计算文件目录
     2   ├── momentum.py
     3   ├── value.py
     4   ├── ...                      # 新增因子只需在此目录加文件
     5   └── registry.py              # 自动发现/注册机制

    5. 标的分类与约束体系
     - 运行策略时，可按规则将标的分类（如大盘股/小盘股等）
     - 每个种类有约束，体现在两个环节：
       1. 组合优化中：约束作为优化器的输入条件（如某类权重上下限）
       2. 组合优化后检查：优化完成后，对结果再做一次约束校验（兜底检查）
     - 分类规则应可配置/可扩展（不局限于大小盘）

    ---

    三、架构原则

     - 量化引擎是独立的 Python 模块，不依赖 Agent
     - 仅通过 Web 服务层与对外接口层暴露其能力
     - 与主观投研共享 Web 服务层与对外接口层，但核心能力层各自独立、互不耦合

    ---

    四、对外接口（本地调用）

     - 接口形式：REST API 为主，可附带 CLI 入口
     - 接口与 Web 页面共用同一套业务逻辑
     - 量化相关接口能力：
       - 查询因子表现
       - 运行指定策略（带参数）
       - 管理标的池（增删）
       - 查询/导出策略结果
